--- SLIDE 4 ---
Introduction
•  Marketplace records span several related files.
•  Manual joins make analysis slow and inconsistent.
•  Operations users need delivery and revenue comparisons.
•  Objectives: clean data, enforce keys and build ten reports.
•  The dashboard connects report results to filters and exports.
--- SLIDE 5 ---
Scope and Methodology
•  Historical Brazilian orders, payments, deliveries and reviews.
•  Analytics uses MySQL queries against the imported dataset.
•  The project excludes checkout and real-time processing.
•  Inspect, clean and import source files.
•  Validate SQL results, then present charts and exports.
--- SLIDE 6 ---
Problem Identification and Analysis
•  Nine linked CSV files complicate consistent analysis.
•  Geolocation repeats zip prefixes. Review identifiers may repeat.
•  Undelivered orders can have missing delivery dates.
•  Operations users need state, timing and revenue comparisons.
•  Normalized storage supports consistent joins and constraints.
--- SLIDE 7 ---
Solution Design and Implementation
•  A repeatable importer cleans and loads the nine source CSV files.
•  Nine normalized MySQL tables and two views support analysis.
•  A read-only Python service runs parameterized report queries.
•  HTML, CSS and JavaScript display the custom local dashboard.
•  A five-minute cache speeds repeated database requests.
--- SLIDE 8 ---
System Architecture
•  Source: nine Olist CSV files from 2016–2018.
•  Storage: nine normalized local MySQL tables and two views.
•  Service: read-only Python HTTP endpoints with query caching.
•  Interface: Overview, Orders, Reports and Database.
•  Output: charts, exact values, SQL display and exports.
